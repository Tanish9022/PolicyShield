# AI Agent Spec

## Role
The AI Agent operates strictly as a `PROPOSER`. It cannot execute actions or change state by itself. It observes Context, Memory, and User Input, and suggests an action to the Policy Gate.

## Capabilities
1. **DISCOVER**: The AI agent translates loose user queries (e.g. "budget phone") into precise product identifiers from the merchant's catalog.
2. **COMPARE & NEGOTIATE**: It reasons over the user's explicit requests and saved preferences against the available products. It proposes a final order configuration, including items, quantities, and discounts.
3. **ADAPT**: If the Policy Gate rejects a proposal, the Agent receives the rejection feedback (reasons for rejection) and modifies its proposal to be compliant, allowing up to 3 adaptation attempts per checkout attempt.

## Bounded Nature
- All proposals generated by the agent must be validated by the `validateRecommendation` gate.
- JIT state (current inventory and real-time prices) fetched immediately before validation overrides any hallucinated context the agent may output.
- Memory constraints: The Agent utilizes the user's explicit preferences as a context factor. However, this Memory is never treated as absolute authority over current conditions or business policy.
